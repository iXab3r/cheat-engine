PerfView – How to capture DBKKernel TraceLogging events

Provider
- Name: EA.DEA64
- GUID: {6bb0f0b0-8c4b-4e0d-9e65-4a2f1f8b2d3a}
- Level: Verbose (5) recommended while testing
- Keywords: 0x0 (the driver does not define keywords, but you can specify 0xFFFFFFFFFFFFFFFF to be safe)

Prerequisites
- Run as Administrator (ETW real-time trace sessions typically require admin).
- Use PerfView v2.0+ (https://github.com/microsoft/perfview/releases/latest/download/PerfView.exe).

Quick start (real-time listening)
1) Open an elevated command prompt.
2) Navigate to this folder (DBKKernel) or anywhere you keep PerfView.
3) Run (if PerfView.exe is on PATH or in the current folder):

   PerfView.exe /CircularMB:256 /BufferSizeMB:64 /OnlyProviders:"EA.DEA64:0x0:5" listen

   - /OnlyProviders uses format: Name[:Keywords][:Level]
   - For TraceLogging providers, Keywords is usually 0x0. Level 5 is Verbose.
   - Use the provider GUID instead of the name if you prefer:

   PerfView.exe /CircularMB:256 /BufferSizeMB:64 /OnlyProviders:"{6bb0f0b0-8c4b-4e0d-9e65-4a2f1f8b2d3a}:0x0:5" listen

4) Confirm you see events like ProviderRegistered and LogLine from the DBKKernel driver.

Collect to ETL file (for sharing/offline analysis)
- GUI:
  1) Launch PerfView as Administrator.
  2) Click Collect -> Run (or Collect -> User Defined Events).
  3) In Additional Providers, add:
     EA.DEA64:0x0:5
     (or {6bb0f0b0-8c4b-4e0d-9e65-4a2f1f8b2d3a}:0x0:5)
  4) Optional: uncheck Kernel providers unless you specifically want them.
  5) Click Start. Reproduce your scenario. Click Stop to save *.etl.zip.

- Command line:
  PerfView.exe collect /OnlyProviders:"EA.DEA64:0x0:5" /NoNGenRundown /NoClrRundown /CircularMB:256 /BufferSizeMB:64 DBKKernelTrace.etl.zip

  Notes:
  - Remove /NoNGenRundown or /NoClrRundown if you also want CLR data.
  - You can add /Merge:true to post-process the ETL automatically.

Viewing the data
- Double-click the produced .etl.zip in PerfView (left tree -> Events).
- Use the Filter box with "EventName=LogLine" to view driver log lines.
- The driver also emits a one-time "ProviderRegistered" event at initialization.

Troubleshooting
- Make sure the driver has registered its provider (you should see a DbgPrint line in DebugView: "DBKKernel: TraceLogging provider registered successfully.")
- Ensure the driver is loaded and its TraceLogging provider is enabled (PerfView listen shows events when enabled).
- If you don’t see events, try the GUID form and set  Keywords to 0xFFFFFFFFFFFFFFFF and Level to 5:

  PerfView.exe /CircularMB:256 /BufferSizeMB:64 /OnlyProviders:"EA.DEA64:0xFFFFFFFFFFFFFFFF:5" listen

- Verify you are Admin and no competing session with same name is blocking (PerfView manages its own session names).
- If you changed the provider name or GUID, update the commands accordingly.

Notes for automation
- You can run PerfView headless on build/test machines using the command-line examples above and collect ETL for later analysis. Use /MaxCollectSec:N to limit capture time.
